# 設計取捨

改介面前先讀這裡，別把已經想清楚的事改回去。

## 借鑑的開源專案

用 `gh repo view` 核過倉庫和簡介；只借互動思路，沒有拷程式碼。KaTeX（MIT）是唯一打包進來的第三方程式碼，在 `assets/vendor/katex/`。

| 專案 | 它怎麼做 | 這裡怎麼用 |
|---|---|---|
| [hypothesis/client](https://github.com/hypothesis/client) | 批註用“原話 + 前後文”（TextQuote）錨到網頁文字，頁面改了也儘量找回；找不到的批註標為孤立，不丟 | 劃線和筆記存 `quote/prefix/suffix`；譯文改動後找不到原話，卡片註明“譯文已改”，筆記仍掛在段落上 |
| [zotero/reader](https://github.com/zotero/reader) | 閱讀器裡劃線、評論、側欄彙總，點批註跳回頁面位置 | 左側抽屜“筆記”頁彙總全部討論和筆記，可篩“待回答”，點選跳回並閃一下 |
| [edwardtufte/tufte-css](https://github.com/edwardtufte/tufte-css) | 寬屏時旁註放在正文右側留白，窄屏收成可點開的標記 | AI 討論和筆記做成邊注，貼著對應段落；窄屏或開啟原頁時收成段尾角標，點開顯示在段落下方 |
| [allenai/scholarphi](https://github.com/allenai/scholarphi) | 在論文原位懸停看引用、符號定義，不用翻到文末 | 引用號懸停看參考文獻；“公式 (4) / 表 2 / 第 2.2 節”懸停預覽、點選跳轉 |
| [immersive-translate](https://github.com/immersive-translate/immersive-translate) | 段落級雙語對照，可整體切換 | “譯文 / 對照”兩種模式，外加逐段“原”按鈕只展開這一段英文 |
| [agentcooper/react-pdf-highlighter](https://github.com/agentcooper/react-pdf-highlighter) | 在 PDF 頁面圖層上框出批註區域 | 原頁面板用字元座標框出當前段落的位置（`layout.json`） |
| [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next) | 譯論文時保護公式和版式，雙語對照 | 公式不走文字翻譯，按原 PDF 用 TeX 重排；原頁始終可看 |

不採用：把譯文塞回 PDF 版式（中文排不進英文的位置，行寬和字號都不適合長讀）；沒有配置引擎時的“問 AI”按鈕（沒有模型就是假按鈕，所以引擎為“不翻譯”時這些按鈕不出現）。

翻譯引擎預設用本機 Claude Code 的無頭模式：不需要 Key，而且它能自己讀原頁圖核對公式和表格；想省錢或離線就換 OpenAI 相容介面（Ollama 本地模型完全免費）。

## 互動

- 頂欄常駐，不隨滾動收起：返回文獻庫、目錄、對照、原頁、筆記、字號、儲存狀態隨時可點。
- 段落操作不藏在懸停裡：點一下段落，段落上方出現帶文字的操作條（Medium / Google Docs 的做法）；右鍵是完整選單（桌面軟體的習慣）；鍵盤 J/K 移動當前段，N/Q/E/R/Y/P 直接操作。
- 選中文字的浮動條參考 Zotero / Readwise：四種顏色劃線、筆記、提問、原文、複製；選中後按 1–4 直接劃線。
- 筆記有兩處：邊注（貼著段落，適合邊讀邊看）和右側筆記面板（按原文順序的全部批註 + 整篇的論文筆記，適合回顧）。
- 字號、版心、行距用滑桿，調的時候閱讀位置不跳。

## 版面

- 一欄正文，約 35 個漢字一行（`--measure: 35em`，18px 時約 630px），行距 1.9，段間距約一行。中文兩端對齊，手機上改左對齊，避免長英文單詞把字距撐開。
- 正文預設宋體（Noto Serif SC / 思源宋體），可切黑體。英文原文用襯線（Source Serif / Charter / Georgia），比正文小一號、灰一級，左側一條細線，和譯文明顯分層。
- 數字統一等高（lining），表格用等寬數字；表格是書籍式三線表，沒有豎線。
- 長公式和寬表格先按比例縮小（桌面最小 72%，手機 58%），再不夠才在塊內橫向滾動，整頁永遠不橫向滾。
- 頂欄 50px，半透明，常駐。每到原文新的一頁，右側留白標一個小小的 p.N，點它看原頁。

## 顏色

暖白紙色底（`#f6f3ec`），墨色字（`#23211d`），不用純黑純白。只有兩個強調色，各管一件事：

- 青（`#2d6173`）：AI 討論，也用於連結。
- 赭（`#9c5f1c`）：我的筆記、我改過的地方。
- 劃線是淡黃底；AI 引用的原話只畫下劃線，不填底色，避免和我的劃線混淆。
- 深色主題是暖黑底（`#1a1917`），正文字重降到 330，避免淺字在深底上顯粗；原頁圖反相顯示。

譯文、AI 討論、我的筆記三者的區分靠字型和位置而不是顏色塊：譯文是正文裡的宋體；討論和筆記是邊注裡的黑體小字，左邊一條細線，標籤寫明“AI · 解釋”“我的筆記”。

## 儲存為什麼可靠

1. 檔案按作者分開：agent 的只寫 paper.json / discussion.json，使用者的只經頁面寫 reader.json，誰也碰不到誰。
2. 頁面先把操作放進瀏覽器 localStorage 佇列，服務端確認落盤後才刪；斷線、服務沒開、頁面崩潰都不丟，下次自動補發。
3. 操作冪等、帶時間戳，重複傳送不會重複或倒退；服務端加鎖、臨時檔案 + 原子替換寫入，另記操作日誌和定期快照。
4. 使用者改過的段落記下改時譯者稿的雜湊；譯者稿後來變了，頁面只提示，使用者選“換成譯者稿”或“保留我的”。
5. 改譯文時草稿每 0.4 秒存一次，誤關頁面再開啟能恢復。
6. 寫介面要頁面載入時拿到的令牌，別的網頁沒法跨站改。
