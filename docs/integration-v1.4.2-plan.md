# v1.4.2 選擇性整合計畫（develop）

## 固定基準與交付

- fork 起點：`87a248a11938e9503f237a4571c3330832d80699`，develop。
- 上游固定來源：`44190260c719377c1503a8587082cfb1313b34e7`（v1.4.2）。
- 以 2026-10-14 的 15 題選擇和最終確認為規格；逐項移植，維持 fork 的平面 Python 模組，不全面搬入上游目錄重構。
- 交付：測試、實際本機操作、可執行的桌面打包驗證，提交／推送 develop。main、正式版號、tag、Release 留待驗收後決定。
- 不呼叫真實 AI。測試使用臨時資料庫、合成 PDF、假模型及假更新事件，避免改動使用者文獻。

## 不變條件

1. 拖曳分隔線維持共用比例、480/420px 最小寬度、1180px 覆蓋切換、雙擊重設、每次頁面開啟恢復預設、閱讀位置補償。灰色視覺不改。
2. `PR.openSide` 保留 splitter 的 refresh hook；不覆蓋 pageview.js 的 fork 實作。
3. 保留繁中、英文／中文主次、原文／譯文的 DOM 身份、雙語配對標記。
4. `lang` 與 `unmarked` 保留；取消標記不得刪除筆記、關聯圖表或讓標記復活。
5. 保留聊天 `attachments` 與 `refs[].source/message/quote`、純照片訊息與多段 AI 回答引用追問。
6. 模型、提示詞、每批頁數、每篇分段並行與資料儲存位置不因移植而被重設。
7. 現有論文開啟、重匯同 PDF、補譯均不得偷偷啟用新版 PDF 重算。
8. 更新來源固定為 an4131754-collab/easyread；禁止 downgrade／prerelease，使用者按更新並重啟後才安裝。

## 先處理的已知衝突

| 衝突位置 | 整合方法 | 必驗收項目 |
|---|---|---|
| 上游 `side: en` vs fork `lang: en` | 相容讀取舊欄位，fork 寫入格式不改；編輯展開既存 note 物件 | 既有中英標記刷新仍在，取消後不復活 |
| 上游不認識 `unmarked` | 篩選、顏色統計、圖表關聯保持 fork 規則 | 取消標記但保留文字與圖表 |
| 新圖表筆記可能沒有文字 | 清理規則需識別有效 `media_refs` | 純圖表筆記不被自動刪除 |
| 上游 chat 缺 fork 附件／回答引用 | 不替換 chat.py、chat_store.py、chat.js；只改設定中的接口辨識 | 附件、純照片、多段追問完整回歸 |
| 搜尋上游永久切雙語 | 獨立 find 模組，保存搜尋開始的模式；隱藏語言命中才暫切，關閉恢復 | 主次選擇不變、標記及公式 DOM 不重寫 |
| 新 PDF 有多頁 regions，而 fork 只有 page/boxes | 加讀取 adapter，同時接受兩種格式；頁面控件与 splitter 維持原樣 | 跨頁定位、框選、手動頁碼、拖曳縮放 |
| 舊版本標記不足以識別新文獻 | 真正 fresh 匯入才加入新策略標記；不依 added 日期判斷 | 舊文獻與重匯不重算 |
| 現有 reader 快照不足以恢復 PDF 更新 | 完整單篇目錄備份；手動更新／恢復皆有忙碌檢查與寫入鎖 | paper/layout/裁圖/notes/chat 可完整還原 |
| 自訂接口共用空 preset 金鑰槽 | 統一 endpoint key ID，翻譯、問 AI、模型列表與 UI 同時使用 | 切換接口不送錯金鑰、舊配置遷移、public 不洩漏 |
| 多篇並行可能清掉新任務 cancel | 拆出單次任務生命週期，僅清理自己的 Event；外迴圈錯誤隔離 | 取消、立即重排、刪除論文、損壞 job 不停整條佇列 |
| macOS／Linux 舊 fork 未啟用更新 | 安裝一版啟用更新的 fork 後才支援；mac 固定 fork 憑證、ZIP；Linux 需 AppImage | 平台 eligibility、feed、忙碌保護、資產完整性 |
